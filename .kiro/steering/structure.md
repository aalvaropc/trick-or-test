# Project structure

```text
.kiro/              specs, steering, hooks, agents, settings/mcp.json
packages/engine/    npm package "trick-or-test": engine, CLI, MCP server, hook entry points
apps/viewer/        static web viewer
examples/pricing/   demo target that the engine attacks
power/              Kiro power: plugin.json, mcp.json, skills/
reports/            committed evidence, generated by `npm run measure`
docs/decisions/     architecture decision records (MADR 4)
scripts/            repository tooling (commit guard), with its own tests
.github/            CI workflows, Dependabot, issue and pull request templates
```

`AGENTS.md` at the root states the workflow and commit rules for every task. A workspace may add its own `AGENTS.md` for rules that apply only there.

## Each spec owns one area

| Spec                          | Owns               |
| ----------------------------- | ------------------ |
| `.kiro/specs/pricing-rules`   | `examples/pricing` |
| `.kiro/specs/mutant-engine`   | `packages/engine`  |
| `.kiro/specs/bestiary-viewer` | `apps/viewer`      |

Change the spec first, then the code.

## Where things go

| You are adding                    | It goes in                                              |
| --------------------------------- | ------------------------------------------------------- |
| A rule of the demo cart           | `examples/pricing/src/`                                 |
| A spec mutant                     | `examples/pricing/mutants/<spec-name>/<mutant-id>.json` |
| Engine logic                      | `packages/engine/src/<area>/`                           |
| An MCP tool                       | `packages/engine/src/mcp/`, plus a row in the README    |
| Types shared by engine and viewer | `packages/engine/src/report/`                           |
| A screen                          | `apps/viewer/src/screens/`                              |
| Anything that draws a creature    | `apps/viewer/src/bestiary/`                             |
| Evidence for the README           | `reports/`, through `npm run measure`                   |

Tests live in each workspace's `test/` folder and mirror `src/`.

## Naming

- Files: `kebab-case.ts`. React components: `PascalCase.tsx`.
- Acceptance criterion ids: `<requirement>.<criterion>`, for example `4.3`. Use the same id in test names, mutant files, reports and UI.
- Mutant ids: `oath-<criterion>-<slug>`, for example `oath-4.3-threshold-before-coupon`.
- Species names are fixed: Borderling, Miscount, Two-Face, Hollow, Impostor, Oathbreaker.

## Boundaries

- `apps/viewer` imports only `trick-or-test/report` from the engine (types and schemas). That subpath has no `node:` imports.
- `packages/engine` never imports from `apps/` or `examples/`.
- `examples/pricing` does not depend on the engine. It is an ordinary project that the engine attacks from outside.
- `reports/` and `apps/viewer/public/demo/` hold generated files. Regenerate them; never edit them by hand.
- Working files of a run go to `.trickortest/` in the target project, which is git-ignored.
